<objective>
Create the food timer lifecycle state layer that connects saved-zone outage
status to local tracked foods.

This plan covers FOOD-03 by detecting saved-zone outages and starting timer
sessions for tracked/enabled foods only, and FOOD-04 by keeping active timers
counting from the best known outage start, including stale/offline status. It
also resets active timers on restoration and enters a review state instead of
silently declaring food safe.

Covers D-04 saved-zone auto-start, D-05 only tracked foods start, D-06 local
offline MMKV state, D-07 restoration review honesty, D-08 stale/unstable
honesty, D-15 prompt or notification instead of silent workflow, D-16 reset on
restoration, and D-18 keep counting while stale/offline.
</objective>

Existing constraints:
- Use `STORAGE_KEYS.selectedZone` as the only zone source. Do not introduce
  multi-zone food tracking.
- Use `StatusJson.regions[selectedZone]` from `useStatus()` as the status
  source. Do not add a new read API.
- Prefer `region.outage.started_at`; if absent, derive outage start from
  `region.outage.elapsed_minutes`; if both are absent during a recognized
  outage, use local detection time and mark source as `detected_at`.
- Keep timers local/offline in MMKV. No backend schema, accounts, sync, pantry
  management, barcode scanning, sensors, or household sharing.

Interfaces to create:
- `FoodTimerSession`
- `deriveFoodTimerSession(input)`

<decision_coverage>
- D-04: A saved-zone active outage starts a food timer session automatically for
  tracked/enabled foods.
- D-05: Auto-start never starts every preset by default; disabled/untracked foods
  are ignored.
- D-06: Timer session state is persisted in MMKV under `foodTimerState`.
- D-07: Restoration produces `restored_review` with factual review copy support;
  it does not declare food safe.
- D-08: Stale/offline/unstable status is exposed to the UI as uncertainty, not
  hidden.
- D-15: A newly detected outage sets prompt/review metadata so the UI or
  notification layer can ask the user to review timers.
- D-16: Restoration resets active timer counting and cancels the active session
  instead of pausing indefinitely.
- D-18: If status is stale/offline while a session is active, elapsed time keeps
  counting from the last known outage start.
</decision_coverage>
