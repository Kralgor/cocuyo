## Spacing Scale

Same 8-point scale as Phase 1. No new tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon-to-label gaps, status dot margins |
| sm | 8dp | Compact spacing, badge padding, parroquia picker gap |
| md | 16dp | Default horizontal padding, card internal padding, report button padding |
| lg | 24dp | Section padding, hero block vertical padding |
| xl | 32dp | Error state horizontal breathing room |
| 2xl | 48dp | Report button minimum height (touch target + visual weight) |
| 3xl | 64dp | Not used in Phase 2 |

Exceptions (Phase 2 specific):
- Report buttons: minimum 64dp height (not 48dp) — the two big "Se fue / Volvió" buttons are primary CTAs that need deliberate tap weight. Extra height prevents accidental taps.
- Battery banner: 40dp fixed height (same as staleness banner — consistent notification strip height).
- Contacts card rows: 48dp minimum height (touch target for tel: dialer tap).
- Parroquia picker rows: 48dp minimum height.
- Share button on hero: 44dp minimum touch target (icon button with hitSlop={8}).

## Color

### Theme Palettes

All Phase 1 tokens carry forward unchanged. AMOLED adds one new theme variant.

#### AMOLED Theme (new in Phase 2)

Extends DARK_THEME. Only bg and panel change to true black. All other tokens inherit from dark theme.

| Token | AMOLED Value | Rationale |
|-------|-------------|-----------|
| bg | #000000 | True black — OLED pixel off = zero power draw |
| panel | #0A0A0A | Near-black panel — visible separation without wasting pixels |
| ink | #F0EBE0 | Same as dark — unchanged |
| inkDim | rgba(240,235,224,0.60) | Same as dark |
| inkFaint | rgba(240,235,224,0.35) | Same as dark |
| accent | #E8C840 | Same as dark — brand constant |
| ok | #5AAA58 | Same as dark |
| warn | #E07530 | Same as dark |
| danger | #D04030 | Same as dark |
| line | rgba(240,235,224,0.08) | Same as dark |
| lineStrong | rgba(240,235,224,0.20) | Same as dark |

MMKV key for theme override: `'themeOverride'` — values: `'light' | 'dark' | 'amoled' | null`. 'amoled' extends dark behavior.

### 60/30/10 Split

- **60% dominant:** bg — all screen backgrounds, safe-area, tab bar, battery banner background uses warn color (exception: semantic communication).
- **30% secondary:** panel — report tab inner surfaces, contacts card, parroquia picker rows, queue state card, share preview container.
- **10% accent:** accent (#E8C840) — reserved for: "Se fue la luz" button fill, active tab indicator, share button icon, GPS resolving spinner, offline queue syncing indicator.

**Accent is NOT used for:** "Volvió la luz" button (uses ok), danger/ok/warn status indicators, battery banner, contacts rows, parroquia picker selection highlight (uses lineStrong).

### Semantic Color Additions (Phase 2)

| Token | Usage in Phase 2 |
|-------|-----------------|
| ok | "Volvió la luz" button fill — power-back report is a positive action |
| danger | No new danger usages — report buttons do not use danger color |
| warn | Battery banner strip background (same role as staleness banner) |
| accent | "Se fue la luz" button fill, GPS spinner, sync indicator |

**Report button color rationale:** "Se fue la luz" = accent (alert, information, not danger — we are not showing danger, we are reporting). "Volvió la luz" = ok (restoration, positive). This avoids the political red/green trap while staying semantically clear.

## Screen-by-Screen Interaction Contract

### 1. Report Tab Screen

**Route:** `mobile/app/(tabs)/report.tsx` — replaces placeholder tab
**Layout:** ScrollView, safe-area top, tab bar at bottom
**Components (top to bottom):**

**A. Screen title row:**
- Title: "Reportar" (Heading 20sp, ink), left-aligned, md horizontal padding
- No gear icon on this screen (gear is zone screen only)
- Height: 48dp

**B. GPS zone detect status strip:**
- Shown always (even when GPS is resolving)
- Height: 40dp, bg background, md horizontal padding
- States:
  - Resolving: "Detectando tu zona…" (Label 13sp, inkDim) + accent ActivityIndicator (12dp, left of text)
  - Resolved: "Zona detectada: {display_name}" (Label 13sp, ink) + Ionicons `location` (12dp, ok color, left of text)
  - Timed out / denied: "Selecciona tu zona manualmente" (Label 13sp, inkDim) + Ionicons `location-outline` (12dp, inkFaint)
- The zone display (resolved or manual) shows tappable link-style underline: Body 16sp, accent color, tap → open ZonePicker
- If savedZone already set: shows saved zone immediately, GPS detection still runs in background to confirm/override

**C. Zone display pill:**
- 32dp height, 8dp border radius, panel background, lineStrong border 1dp
- Left: Ionicons `location-sharp` (14dp, inkDim) + 4dp gap + zone display_name (Label 13sp, ink)
- Right: Ionicons `chevron-forward` (14dp, inkFaint)
- Full width minus md horizontal margin
- Tap: open ZonePicker (same as Settings "Cambiar zona")
- marginBottom: 16dp (md)

**D. Two report buttons:**

Layout: two full-width buttons, stacked, md gap between them, md horizontal margin.

Button 1 — "Se fue la luz" (outage report):
- Height: 64dp
- Background: accent (#E8C840) — both themes
- Text: "Se fue la luz" (Heading 20sp, 700, ink color — #1A1A1A on yellow is AAA)
- Icon: Ionicons `flash-off` (24dp, ink color), 8dp gap to text, icon LEFT of text
- Border radius: 8dp
- accessibilityRole="button", accessibilityLabel: "Reportar corte de luz"
- Disabled state: opacity 0.4, non-tappable (during cooldown or submission)

Button 2 — "Volvió la luz" (restoration report):
- Height: 64dp
- Background: ok color (theme.ok) — #3A7A38 light / #5AAA58 dark / #5AAA58 AMOLED
- Text: "Volvió la luz" (Heading 20sp, 700, #FFFFFF always — ok color guarantees contrast)
- Icon: Ionicons `flash` (24dp, #FFFFFF), 8dp gap, icon LEFT of text
- Border radius: 8dp
- accessibilityRole="button", accessibilityLabel: "Reportar regreso de luz"
- Disabled state: opacity 0.4, non-tappable (during cooldown or submission)

**E. Cooldown notice (conditional):**
- Shown only when within 30-minute client-side dedupe window
- Label 13sp, inkFaint, centered
- Copy: "Ya reportaste hace {N} min — espera {M} min para reportar de nuevo" (ES) / "You reported {N} min ago — wait {M} min to report again" (EN)
- marginTop: 8dp (sm)

**F. Offline queue status card (conditional):**
- Shown only when queue has pending items (count > 0)
- panel background, 8dp border radius, md padding, md horizontal margin, md top margin
- Header row: Ionicons `cloud-offline-outline` (16dp, warn) + "Reportes pendientes: {N}" (Label 13sp, warn), 4dp gap
- Body: "Se enviarán automáticamente al volver la conexión" (Label 13sp, inkDim)
- No dismiss — auto-hides when queue empties

**G. Optional parroquia picker (conditional, after button tap):**
- Not shown on initial load — appears as bottom sheet after button tap, before final confirm
- See "Report Confirm Flow" interaction below

**Interaction — Report Confirm Flow:**

1. User taps "Se fue la luz" or "Volvió la luz"
2. If zone not resolved yet: show "Esperando zona…" toast, block submit
3. If zone resolved: bottom sheet slides up (280ms, same as SettingsModal)
   - Bottom sheet height: ~50% screen
   - Handle: 36dp wide, 4dp, lineStrong, centered
   - Header: "Confirmar reporte" (Heading 20sp, ink) + close icon (Ionicons `close`, 24dp, inkDim)
   - Zone confirmation row: "Zona: {display_name}" (Body 16sp, ink), non-tappable label
   - Parroquia row: "Parroquia (opcional)" (Label 13sp, inkDim) → cascading picker
     - Picker shows municipio selector first, then parroquia selector
     - Both are ScrollView-based lists, not native Picker (consistent with React Native StyleSheet approach)
     - Municipio rows: 44dp height, Body 16sp, ink, checkmark (Ionicons `checkmark`, accent) when selected
     - Parroquia rows: same style
   - Confirm button: "Enviar reporte" (Body 16sp, 700, ink), accent fill, 48dp height, 8dp radius, full width minus md padding
   - Cancel: tap outside sheet or close icon — dismisses without submitting

4. On confirm tap:
   - Button shows ActivityIndicator (accent, 16dp) replacing text
   - Submit to Supabase (or enqueue if offline)
   - On success: bottom sheet closes, toast appears (see Toast spec below)
   - On error: toast appears with error copy, sheet stays open for retry

**Toast spec:**

Toasts appear at bottom of screen, above tab bar, lg margin from bottom.

| Trigger | Copy (ES) | Copy (EN) | Color | Duration |
|---------|-----------|-----------|-------|----------|
| Report submitted (online) | "Reporte enviado. ¡Gracias!" | "Report sent. Thank you!" | ok background | 3s |
| Report queued (offline) | "Guardado — se enviará al volver la conexión" | "Saved — will send when connection returns" | warn background | 4s |
| Sync completed (background) | "Reporte pendiente enviado" | "Pending report sent" | ok background | 3s |
| Submit failed (online, retry) | "No se pudo enviar. Inténtalo de nuevo." | "Could not send. Try again." | danger background | 4s |

Toast visual: 40dp height, md horizontal margin, 8dp border radius, white text (Label 13sp, #FFFFFF always — semantic background guarantees contrast). Ionicons icon left of text (16dp, #FFFFFF):
- ok: `checkmark-circle`
- warn: `cloud-offline-outline`
- danger: `alert-circle-outline`

Toast does NOT block the UI. It slides up from bottom, auto-dismisses, no tap required.

### 2. Zone Detail Screen (additions to Phase 1)

**Route:** `mobile/app/(tabs)/index.tsx` — existing screen, extend only

**A. Share button on StatusHero:**
- Position: absolute top-right corner of StatusHero block, 8dp from top and right edges
- Visual: Ionicons `share-social-outline` (20dp, rgba(255,255,255,0.80))
- Touch target: 44dp × 44dp (hitSlop={12} around 20dp icon)
- accessibilityRole="button", accessibilityLabel: "Compartir estado por WhatsApp" (ES) / "Share status via WhatsApp" (EN)
- Tap: trigger share flow (see Share Flow below)
- Shown: always when region data is available (not during skeleton/error states)

**B. "Números útiles" contacts card:**
- Position: bottom of ScrollView, below signal cards, above last-updated row
- Shown: always when region data available and contacts exist for the region's state
- Structure:
  - Section header: "Números útiles" (Label 13sp, inkDim, uppercase, md left padding, sm vertical padding)
  - panel background container, 8dp border radius, md horizontal margin, no internal padding (rows provide their own)
  - Divider: line color, 1dp between rows
- Contact row: 48dp height, md horizontal padding, flexDirection row
  - Left: Ionicons `call-outline` (18dp, accent) + 8dp gap + contact name (Body 16sp, ink)
  - Right: contact number (Label 13sp, inkDim)
  - Tap: `Linking.openURL('tel:{number}')` — opens native dialer
  - accessibilityRole="button", accessibilityLabel: "{name}: {number}. Toca para llamar."
- If no contacts data for state: section is hidden entirely (no empty state — just absent)

**Contact data shape (bundled JSON):**
```
{ state_key: { contacts: [{ name: string, number: string, verified: boolean }] } }
```
- verified: true = confirmed number, false = "Por verificar" suffix on number display (Label 13sp, warn color, italic — signals caution without hiding the number)

**C. Post-report share prompt (conditional):**
- After successful "Se fue la luz" report, a prompt appears in zone screen (not toast)
- Placement: inline card below staleness banner, above hero
- Height: auto, panel background, warn border 1dp, 8dp radius, md padding, md horizontal margin
- Copy: "¿Avisas a tus vecinos?" (Body 16sp, ink, bold) + "Comparte el estado de tu zona en WhatsApp" (Label 13sp, inkDim)
- Right side: share button "Compartir" (Label 13sp, accent, 700) — tappable, not a full button
- Dismiss: Ionicons `close-outline` (18dp, inkFaint), top-right of card, 44dp touch target
- Auto-dismiss: after 30 seconds or after user taps share
- Only shown once per report session (not on every app open)

### 4. Battery Savings Banner

**Route:** global, rendered in root layout or per-tab, above tab bar (or below header)
**Placement:** 40dp strip immediately below screen header (same position as staleness banner — do not stack; battery banner takes precedence over staleness banner if both are true, show only battery banner)

## Share Flow — Full Interaction

1. User taps share button (on hero) or "Compartir" in post-report prompt
2. Compose share string from current region data (status, outage, eta if present)
3. `Linking.canOpenURL('whatsapp://send')` check
   - true: `Linking.openURL('whatsapp://send?text={encoded_string}')` — opens WhatsApp directly
   - false: `Share.share({ message: share_string })` — opens system share sheet
4. No success/error toast after share — user sees WhatsApp/system sheet directly

---

## AMOLED Flow — Full Interaction

1. Settings modal → Apariencia → tap "AMOLED"
2. MMKV `'themeOverride'` set to `'amoled'`
3. ThemeContext re-computes — app re-renders with AMOLED_THEME (bg: #000000, panel: #0A0A0A, all other tokens from DARK_THEME)
4. No restart required — same live-context pattern as light/dark switch

**ThemeContext extension:** `type ThemeOverride = 'light' | 'dark' | 'amoled' | null`. The `useTheme()` hook resolves AMOLED_THEME when override is `'amoled'`, same guard as dark.

---

## Battery Mode Flow — Full Interaction

1. expo-battery `useBatteryLevel()` listener fires when battery < 0.20
2. App sets local state `isBatterySaving = true`
3. Battery banner appears (40dp strip, warn bg)
4. useStatus refresh interval switches from 600_000ms (10 min) → 1_800_000ms (30 min)
5. Any Animated.loop calls in active screens call `.stop()` (shimmer, etc.)
6. User taps banner → `setBannerDismissed(true)` (session state, no MMKV) → banner hides
7. Battery mode remains active even after banner dismissed — only visual changes

## New TypeScript Interfaces (for executor reference)

```typescript
// Report submission payload — mobile/lib/api.ts addition
// Matches web app/lib/api.ts:95 payload shape + nullable parroquia column
interface ReportPayload {
  region:             string;          // region key e.g. "maracaibo"
  status:             'no_power' | 'power_back';
  lat:                number | null;   // GPS lat if available
  lon:                number | null;   // GPS lon if available
  city_freetext:      string | null;   // always null (mobile uses region key)
  onset_type:         null;            // Phase 2: always null
  symptom:            null;            // Phase 2: always null
  device_fingerprint: null;            // ADR-005: deferred to Phase 4
  parroquia:          string | null;   // NEW: nullable — web sends null, mobile sends if selected
}

// Offline queue item — mobile/lib/storage.ts addition
interface QueuedReport {
  id:        string;        // uuid — for deduplication
  payload:   ReportPayload;
  queued_at: string;        // ISO 8601 timestamp
  attempts:  number;        // retry count
}

// Contact entry — bundled contacts JSON
interface ContactEntry {
  name:     string;
  number:   string;         // normalized: digits + "+" only e.g. "+58-800-000-0000"
  verified: boolean;        // false = "Por verificar" label shown
}
```
