<objective>
Implement pipeline-side push notification fan-out for D-06 saved-zone neighbor adjacency, D-09 confirmed lifecycle cooldown, D-10 unstable/bajones suppression, and D-11 Spanish-first factual no-ETA copy.
The pipeline must read `push_tokens`, apply unstable/cooldown
suppression, send Expo Push API messages in batches, log notification attempts,
and continue the pipeline when notification delivery fails.

Covers D-06 neighbor warnings from saved-zone adjacency with no separate zone
selection; D-09 confirmed lifecycle transitions plus per-zone/per-event-type
cooldown; D-10 unstable/bajones suppression; and D-11 Spanish-first, factual
notification copy with no invented ETAs.

Decision text carried forward:
- D-06: Use a hand-curated, symmetric adjacency map over the 17 canonical zones
  (geography + national grid awareness). Neighbor warnings derive from the
  saved zone's neighbor list — no separate zone selection.
- D-09: Two-part suppression: only notify on CONFIRMED/stable transitions, not
  every 10-min cycle flap; per-zone, per-event-type cooldown window. Build on
  existing `outage_lifecycle.py` and `restoration_tracker.py` rather than raw
  cycle-to-cycle diffs.
- D-10: Suppress notifications while a zone is in `unstable` status (bajones)
  — do not fire out/back on every flap. Only fire when the lifecycle confirms
  a real outage start or restoration.
- D-11: Notification copy is Spanish-first, factual, consistent with the app's
  honesty principle. No invented ETAs.
</objective>
