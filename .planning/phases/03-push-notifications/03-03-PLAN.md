## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile (anon key) → push_tokens | Untrusted anonymous device input writes token + zone + prefs. |
| pipeline (service_role) → push_tokens / notification_log | Trusted CI reads tokens and writes cooldown log. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | anon writes to push_tokens (spoof other rows, escalate columns) | mitigate | Column-scoped GRANTs: anon may INSERT only (expo_token, zone, platform, notify_*) and UPDATE only (zone, notify_*, updated_at). anon cannot write id/created_at or arbitrary columns. CHECK constraints bound platform and event_type. |
| T-03-05 | Information Disclosure | anon SELECT on push_tokens enumerates tokens | accept | anon SELECT is required for PostgREST upsert conflict resolution (RESEARCH Pitfall 4). push_tokens holds NO PII (ADR-005, no device_fingerprint); tokens are not secret and are project-validated by Expo. Residual enumeration risk accepted; documented in RESEARCH Security Domain. |
| T-03-06 | Tampering | anon writes to notification_log (forge cooldown / inject) | mitigate | notification_log has NO anon policy and NO anon GRANT — RLS default-deny. Only service_role (RLS-bypass) can read/write. Verified by grep count == 0 for `notification_log TO anon`. |
| T-03-07 | Denial of Service | anon bulk-INSERT fake tokens (fan-out amplification) | accept | Partial mitigation only at this layer: Expo per-project rate limit (600/s) + per-zone per-type cooldown (plan 05) cap amplification. Volume-based abuse rate-limiting (Cloudflare/Supabase in front of PostgREST) is a documented residual risk, not closed in Phase 3. |
| T-03-SC | Tampering | npm/pip installs | accept | No package installs in this plan (SQL + Python constant + docs only). RESEARCH Package Legitimacy Audit present. |
</threat_model>
