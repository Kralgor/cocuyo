<objective>
Resolve the BLOCKING, non-automatable prerequisite flagged by RESEARCH: Android
push delivery requires Firebase FCM V1 credentials in EAS, and the pipeline's
auth header depends on the EAS push-security setting. This plan pauses for the
human to perform Firebase/EAS dashboard steps that Claude cannot do via CLI.

Purpose: Without FCM credentials, the entire pipeline can build, register tokens,
and even POST to Expo successfully while NO notification ever reaches an Android
device (silent failure — RESEARCH Pitfall 7). This checkpoint prevents the phase
from falsely "passing" with no real delivery path.
Output: FCM credential uploaded; push-security decision recorded; EXPO_ACCESS_TOKEN
either added to GitHub Actions env cocuyo or explicitly marked not-needed.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer → Firebase / EAS / GitHub secrets | Credentials (service-account JSON, Expo access token) are created and stored in third-party dashboards and CI secret stores. |
| pipeline (CI) → Expo Push Service | The pipeline authenticates to Expo using EXPO_ACCESS_TOKEN when push security is on. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02 | Information Disclosure / Elevation of Privilege | EXPO_ACCESS_TOKEN and FCM service-account JSON | mitigate | Secrets live ONLY in GitHub Actions environment `cocuyo` and EAS-managed credential store. Never committed to the repo, never placed in mobile/ or any client-readable file (CLAUDE.md). Service-account JSON is uploaded to EAS, not stored in git. |
| T-03-03 | Spoofing | Unauthenticated Expo push sends (if push security off) | accept | Expo validates that each push token belongs to project 53f480cb; a third party cannot push to your tokens without them. Residual risk accepted; enabling push security (this plan's decision) is the optional hardening. |
| T-03-SC | Tampering | npm/pip installs | accept | No package installs in this plan (dashboard/CLI credential work only). |
</threat_model>
